# IdleShift

[English](README.md) | 日本語

> 公開前の下書きです。実装済み・条件付き・未実証の区別は [docs/self-study/REPORT.md](docs/self-study/REPORT.md) の2章を正とします。

複数の MCP 対応 AI アプリ（Claude / Codex / Antigravity など）を、PC 内の 1 つの常駐アプリにつなぎ、**目的・タスク・仮説・根拠・許可・予算・停止**をまとめて管理するローカルアプリです。黒板（blackboard）はアプリに内蔵され、利用者がファイルやフォルダー構成を管理する必要はありません。

- 版：0.1.0（初版。実装状況と未検証は末尾）

## 使い方

### 配布物から（一般利用者向け・コマンド不要）

1. `npm run dist` で作った `dist\IdleShift-0.1.0-win-x64.zip` を展開し、`Install-IdleShift.cmd` をダブルクリック（配布物は未署名・未公開。今の `dist/` に残っている改名前の古い配布物は使わないこと）。
2. デスクトップの「IdleShift」を開く。
3. 「ホーム」でプロジェクトを作り、作業フォルダーを登録 →「接続」で AI アプリに登録 → ゴールを書いて開始 →「開始の一言」を AI アプリに貼り付ける。

Node.js の別途導入は不要です（実行環境を同梱）。更新は新しい版の `Install-IdleShift.cmd` を実行するだけで、データと接続設定は引き継がれます。

### ソースから（開発者向け）

```
node bin/idleshift.mjs gui      # サービスを起動して画面を開く
node bin/idleshift.mjs hosts    # 各AIアプリの検出・登録状況
node bin/idleshift.mjs stop     # サービスを止める
npm test                         # 自動テスト
npm run dist                     # 配布物を作る
```

Node 22.13 以上（内蔵 SQLite を使用。CI は Node 24）。npm 依存はゼロです。

## 構成

```
AIアプリ(Claude/Codex/Antigravity…)          人
   │ stdio (MCP)                              │ ブラウザー窓（127.0.0.1 のみ）
   ▼                                          ▼
 中継 relay.mjs ──名前付きパイプ(トークン認証)──▶ 常駐サービス service.mjs
 （状態なし・DBを開かない）                      ├ core.mjs   状態機械・権限・予算（唯一の判定者）
                                                ├ db.mjs     SQLite（正本。開くのはサービスだけ）
                                                ├ hosts.mjs  AIアプリへの登録（差分表示・控え・取消）
                                                └ adapters.mjs CLI起動（任意・既定は無効）
```

- GUI と MCP は同じ `Core` を通るので、状態・権限・判定が二重になりません。
- MCP 用にポートは開きません（stdio 中継＋名前付きパイプ）。GUI だけが 127.0.0.1 の無作為ポートを使い、トークン・Host/Origin 検査・サイズ/頻度制限・厳格な CSP を付けています。
- データは現在 `%LOCALAPPDATA%\IdleShift`（同期フォルダー外）。**Claude デスクトップ（ストア版）から起動すると、この場所が別の場所に振り替えられてデータが分かれる不具合があり、`%USERPROFILE%\.idleshift` への移行を予定しています（[docs/data-home.md](docs/data-home.md)）。**インストール先は `%LOCALAPPDATA%\Programs\IdleShift` で固定なので、更新しても AI アプリ側の登録は壊れません。

## MCP ツール（7 個・標準機能のみ）

| ツール | 役割 |
|---|---|
| `join(root)` | 作業フォルダーからプロジェクトを解決して参加。未登録なら未登録と返すだけ（推測しない）。文脈を失った後の復帰にも使う |
| `next(participant, wait_seconds)` | 次の仕事の提示。`offer / resume / none / stop / superseded`。`wait_seconds` を付けると仕事が来るまで保留 |
| `claim(task, gen)` | 引受け。ここで初めて「作業中」になり、依頼内容を受け取る |
| `get(ref, limit, cursor)` | 黒板の必要部分だけ読む（ページング） |
| `report(...)` | `progress / result / decline / blocked / decision_needed / limit`。追記のみ、`report_id` で二重登録防止 |
| `plan(goal, base_version, ops[])` | 小目標・仮説の枝・根拠・要約・受入/差戻し・完了候補の提案。版・予算・委任範囲を検証し、全部適用か全部拒否 |
| `status()` | 読取専用の全体像 |

sampling・サーバー発の通知などのオプション機能は使いません（基本 MCP だけのクライアントでも全機能が使えます）。

## 割当の状態機械

```
open → offered(提示期限120秒) → claimed(担当期限30分・進捗報告で延長) → reported → accepted
                │ 期限切れ：試行数を消費せず open へ      │
                                                        ├ 辞退・上限報告・読取タスクの期限切れ → open（世代+1）
                                                        ├ 書込みタスクの期限切れ → needs_check（人が判断。自動で別担当へ渡さない）
                                                        └ 質問 → parked（人の回答で同じ担当へ再提示）
```

- 同じタスクの有効な担当は常に 1 つ。古い世代・別人からの報告は「遅延結果」として保存するだけで状態を変えません（報告IDも送信者ごとに管理され衝突しません）。
- 権限撤回や依存先取消が発生した場合、未着手タスクは安全に取消・保留へ遷移し、作業中タスクは無言で破棄されず `recheck` フラグと判断待ち（再開または取消）が人に提示されます。
- サービス再起動やバックアップ復元後は、旧セッションの混同を防ぐため最初の呼出しが `rejoin_required` を返します。`join` を再度呼ぶことで参加情報と担当タスクが安全に復元されます。
- 進行役（会議）は常設の役割ではなく、**「進行中のゴールに、やること・判断待ちが何もない」ときにプログラムが 1 件だけ作るタスク**です。新しい根拠なしに進行役が 3 回続くと人へ戻します。
- 予算は数えられる単位だけ：割当回数（既定 30）、同時作業 2、枝 2、差戻し 3、無進展 3、期限。担当や名前を変えてもリセットされません。上限到達は判断待ちになります。
- ゴールの完了は AI の申告では「完了候補」まで。人が確定します。

## 階層別の割り振りと使用量の相互管理

**原則：数えるのは IdleShift、判断は進行役 AI、決めるのは人。** 階層や使用量の上限は人が GUI（「接続」タブの参加者一覧）でのみ設定でき、MCP から AI 自身が変更する手段はありません。何も設定しないプロジェクトでは従来と完全に同じ動きになります。

- **参加者の階層（`planner` / `senior` / `worker` / 未設定）**：参加者（会話の `label`）ごとに人が GUI で設定します。同じ名前で再参加しても設定と使用量を引き継ぎます。未設定の参加者はどの階層のタスクも受けられます。
- **タスクの階層（`planner` / `senior` / `worker` / `any`、既定 `any`）**：`plan` の `add_task`（および内部 API の `addHumanTask`）で指定できます（GUI のタスク直接追加ダイアログからは既定の `any` で作成されます）。進行役タスクは、プロジェクトに有効な `planner` 参加者がいる場合は `tier='planner'` で作成され、`planner` が不在または上限中で猶予期間（5 分）を過ぎた場合は進行を止めないよう誰でも受けられます（この救済時は降格レビューの対象にはならず、進行役の成果に `planner` のレビューは自動で付きません）。
- **割り振りの優先順と降格ポリシー**：
  1. 担当の希望（`prefer`）があれば最優先。
  2. タスクの `tier` と階層が**完全一致**する参加者を優先します。上位の参加者（または階層未設定の参加者）が下位タスクを取るのは、該当階層の参加者がプロジェクトに 1 人もいないときは即座に、いるときは未着手から 5 分（`preferGrace`）経過しても該当階層の待機者がいない（または上限中・除外の）ときです。
  3. 既定では「上位は下位の仕事を受けてよい、下位は上位の仕事を受けない」規則です。プロジェクト設定で「一定時間（N 分）後に 1 つ下の階層へ任せる」を有効にすると、上位が不在・上限中のまま N 分経過した `work` タスクを 1 つ下の階層が引き受けられます。降格で引き受けたタスクの成果には、完了報告後に作成者除外・`tier='senior'` のレビュータスクが自動で必須になります（レビュータスク自体は下位へ降格せず、報告時や `plan` の `accept` でも明示的な `worker` 階層による承認は拒否されます。階層未設定の参加者は互換規則により従来どおりすべてのタスク・レビューを担当できます）。
- **使用量の計測と上限（直近 5 時間・直近 7 日）**：
  - IdleShift が名前（`label`）単位で**引受け件数**（初回の `claim` 回数。再開や再取得、`progress`、重複・遅延報告は加算しない）と**作業時間**（初回 `claim` から最終報告・解除までの合計分、切り上げ）を直近 5 時間・7 日の時間窓で計測します。
  - **計測の限界**：計測しているのは引受け件数と経過時間であり、**各 AI サービスのトークン消費量や課金額ではありません**。また、作業時間には PC のスリープ中の経過時間も含まれます。バックアップを復元した場合は、`usage_log` もバックアップ時点へ戻るため、復元直後は使用量が少なく見えます。
  - 人が設定した 4 つの上限（5 時間／7 日の件数・分）のいずれかに達した参加者には、窓から抜けるまで新しいタスクを提示しません（現在担当中の作業は止めません）。
- **見える化**：GUI の参加者カードに階層・直近 5 時間／7 日の使用量・上限までの残り・提示控え中の回復目安を表示します。MCP の `board` と `header`（`your_tier`）、`assignment.program`（`tier` と降格レビューの有無）にも公開され、進行役 AI が `prefer` や `tier` を判断する材料になります。

## プロジェクトのアーカイブと削除

ホームまたはプロジェクト設定から操作できます。アーカイブ済みは通常の一覧で隠れ、「アーカイブ済みを表示」を有効にすると表示できます。

- **アーカイブ**：ゴール・参加者・タスク・報告・登録フォルダーを保持したまま、新規参加と仕事の配布を止めます。待機中の `next` は `stop` を返します。提示中・作業中・要確認のタスク、未回答の判断がある場合は拒否されるため、先に解決してください。未着手の仕事は解除後に再開でき、全体停止の設定も保持します。
- **アーカイブ解除**：元のプロジェクトを再利用できます。アーカイブ中も登録フォルダーの所有権は保持され、別のプロジェクトへ重複登録できません。
- **削除**：ゴール・参加者・タスク等の履歴が一切ない空のプロジェクトだけが対象です。名前入力による確認が必要で、元に戻せません。履歴があれば `project_not_empty` として拒否し、アーカイブを案内します。登録フォルダーと、そのプロジェクトに属する保留中の登録要求も消えますが、ディスク上の作業フォルダーやファイルは削除しません。

DB は v5 への移行時に `projects.archived_at` を追加します。既存プロジェクトは有効のまま移行され、既存 DB の移行前には自動バックアップを作ります。アーカイブ中にサービスを再起動・復元した場合も、旧参加者の `next` は接続を再登録せず停止応答だけを返します。

## 安全設計

**強制（IdleShift が判定）**：割当・世代・予算・全体停止・参加の取消・書込みタスクを作れるか・他プロジェクトの参照拒否・返すデータの範囲。MCP 経由で AI 自身がこれらを緩める手段はありません。

**依頼（AI への指示。実効性は AI アプリ側の権限設定に依存）**：ファイル変更、コマンド実行、依存導入、外部アクセス。IdleShift は AI が自分のアプリの機能で行う操作を止められません。画面にもそう表示しています。

- **通信**：本体はインターネット・LAN へ一切通信しません（更新確認・テレメトリー・使用枠の照会もなし）。AI サービスとの通信は各 AI アプリ（または有効化した CLI）が行います。
- **他 AI の文章**：別の AI が書いたタスク文は `untrusted_ai_text` として、人が書いた内容・プログラムが保証する値と分けて渡します。画面では AI・ファイル由来の文字列をすべて文字として表示し、リンクはクリックできません。
- **脅威モデル**：対象は AI の誤り・取り違え、外部資料由来の指示による逸脱、ブラウザー経由のアクセス、他プロジェクトの参照。同じ Windows ユーザー権限で動くマルウェアは対象外です。
- **使用枠**：`known / stale / unknown / limit_reported`。情報源は人の入力と AI の報告だけ。全員 `unknown` でも割当は動きます。回復予定時刻の到達は「1 回試してよい」であって回復の確認ではありません。
- **参加者**：参加した AI にはプロジェクトの内容が渡り、そのベンダーへ送られ得ます。画面で参加を取り消せます（取り消しは人が再許可するまで有効）。参加者の同一性は「接続＋名前（`label`）」で識別され、参加取消はその名前（および取消時点の接続）に対して効きます。Antigravity のように複数ウィンドウで 1 つの MCP 接続を共有するアプリでも、異なる `label` を付ければ別の会話として並行参加できます。その反面、AI が「同じ接続のまま別の新しい名前で参加して取消を逃れる」ことや「新しい接続＋新しい名前で参加する」ことは新しい会話と区別できないため、名前単位の取消だけでは防げません。アプリ全体を遮断したい場合は、参加者一覧の「このアプリからの新規参加を拒否」を使用してください（既定は許可）。また、担当タスクのない不要な参加者は画面から削除でき（履歴や報告の ID は保持）、削除した名前で再参加した場合は新しい参加者として扱われます。
- **バックアップ・復元保護**：復元時に DB 単体の巻き戻しによってタスク ID や世代番号が過去値に逆戻りして重複・誤適用されるのを防ぐため、外部ファイル `restore-watermark.json` で単調増加ハイウォーターマークを永続管理します。ウォーターマークが破損・改ざんされている場合は安全のため復元を拒否します。

## 能力段階（アプリ名ではなく、この端末での実測で表示）

| 段階 | 意味 | 表示条件 |
|---|---|---|
| L0 | 参加できる | join の成功 |
| L1 | 一言ごとに継続（全アプリの基本体験） | claim→report を 1 回完了 |
| L2 | 待機中に人の操作なしで次の仕事へ進む | 保留中に届いた仕事を完了した実績 3 回以上 |
| L3 | 上限到達後に待機から自動再開 | その実例が 1 回以上 |

保留できる長さもアプリごとに自動で測ります（50 秒から始め、応答が受理されたら倍に延ばし、途絶えた長さの 8 割を上限にする）。アプリの版が変わると未確認に戻します。「待機中」は **未完了の待機呼出しをサービスが実際に保持している状態**だけを指し、接続があるだけの会話は「再開が必要」と表示します。

## 草案の穴と、今回入れた対処

承認不要で盛り込んでよいとの指示に基づき、独立レビュー（F1〜F24）の指摘を次のとおり実装に反映しました。

| 穴（草案のままだと起きること） | 対処 |
|---|---|
| F1 ターンが終わった会話へ割当が消える | 「待機中」を保留中の呼出しに限定。それ以外は「再開が必要」＋開始の一言を正式な再開手順に。3 分放置で OS 通知 |
| F2/F3 枠切れは待機前に起きる・待機コスト | 回復後再開を約束しない（L3 は実例があるときだけ表示）。待機の空振り回数を「待機コストの目安」として表示。タイムアウト応答は最小限の JSON |
| F4 使用枠はほぼ不明になる | 4 状態モデル。クラウド照会・他アプリの認証値読取りはしない |
| F5 許可は IdleShift を通る操作にしか効かない | 「強制」と「依頼」を分けて表示・伝達 |
| F6 世代番号では重複実行を防げない | 書込みタスクは期限切れでも自動再割当せず「要確認」。元の担当が戻れば続行、人が再割当するなら次の担当に「痕跡確認」を付ける |
| F7 応答を書いた≠受け取られた | offer→claim の 2 段階。提示期限切れは試行を消費しない。待機の重複は新しい方だけ残す |
| F8 全員が待機すると誰も計画しない | 進行役タスクの自動生成（1 件だけ・最長待機者へ）。計画は `plan_version` の比較更新 |
| F9 stdio はアプリごとにプロセスが増える | 固定位置の中継＋名前付きパイプ＋単一サービス。サービスが止まっていれば中継が起動 |
| F10 停止ボタンがない | 全体停止（保留中の待機へ `stop`、作業中には次の呼出しで伝達）。閉じた枝へ遅れて届いた結果は保存するが結論に使わない |
| F11 循環と予算 | 数えられる予算＋既定値。根拠なしに過去の担当へ戻す付け替えは拒否 |
| F12 割当文が指示の洗浄経路になる | AI 生成の欄を「信頼しないデータ」として分離 |
| F13 圧縮で ID が消える | 全応答に現在地ヘッダ。`join(root)` で担当中タスクが戻る。再開時は世代を上げて古い写しを無効化 |
| F14 参加者の同一性 | クライアント名は MCP ハンドシェイクから取得。パイプはユーザーだけが読めるトークンで認証。秘密値を AI に渡さない |
| F15 フォルダー登録の手順が消えていた | GUI のフォルダー選択で登録。検索時に正規化＋最長一致。1 フォルダー 1 プロジェクト。パス差異の警告・自動切替はしない（ユーザー指示どおり） |
| F16 オフラインで古くなる | この端末の実測を版つきで保存。ビルドからの日数を表示し半年で注意。更新前に自動バックアップ |
| F17 承認ダイアログが無人実行を止める | 実機で確認（Codex CLI が MCP 呼出しの承認で停止）。IdleShift 自身の 7 ツールだけを事前承認する設定を登録内容に含め、画面で明示。ファイル変更等の承認は変えない |
| F18 最後の一歩が未定義 | コピーできる「開始の一言」（1 回ずつ／待機継続の 2 種）。登録は人のクリック＋内容表示＋控え＋取消 |
| F19 GUI が通信経路になる | CSP で外部読込をすべて禁止、文字列表示のみ、リンクはコピーのみ |
| F20 スリープ・再起動 | tick の空白を検知して期限を延ばす。起動時に提示を open へ戻す |
| F22 現在地の上書き | 報告・根拠は追記のみ。要約は比較更新。棄却理由は別行で残る |
| F23 通知手段 | 判断待ち・要確認・再開が必要を OS のローカル通知で（文面にプロジェクトの内容は入れない） |
| F24 どの会社へ渡るか | 参加者一覧と参加の取消 |

草案にもレビューにもなく、作りながら見つけて入れたもの：

- **CLI 起動アダプター（任意・既定は無効）**：MCP サーバーは終わった会話を起こせない、という根本の穴を埋める唯一の手段として追加。待機者がいないときだけ公式 CLI（`claude -p` / `codex exec`）を起動します。通信の主体は CLI であることを画面に明記し、アプリの待機方式とは別の仕組みとして表示します。1 時間あたりの起動上限、モデル指定、読取のみ／書込み可の選択つき。
- **起動の空振り防止**：他の担当に予約されたタスクしかないときは CLI を起動しない（実機検証で 2 回の空振りを確認して修正）。
- **レビュー担当の分離**：`review: true` のタスクは、作成者以外に自動でレビュータスクが出ます。
- **人からの直接操作**：追加の指示、タスクの直接追加、Markdown での持ち出し、プロジェクトのアーカイブと空プロジェクトの削除。
- **登録待ちフォルダー**：AI が未登録フォルダーから参加しようとした記録を画面に出し、人がクリックで登録（AI の申告だけでは登録しない）。

レビューが「ユーザー判断が必要」とした 4 点は、ひとまず次の値で進めています（変更可）。

| ID | 採用 |
|---|---|
| D1 外向き通信なしに「本体が起動する子プロセス」を含めるか | 既定は含める（子プロセスなし）。CLI アダプターは明示的に有効化したプロジェクトだけの例外 |
| D2 ホストの MCP 設定をクリックで書いてよいか | 許可（内容表示・控え・取消つき）。Claude Code だけは公式コマンド `claude mcp add-json` 経由 |
| D3 無人継続できないとき L1 を製品として受け入れるか | L1 を基本体験とし、CLI アダプターを任意の別機能として追加 |
| D4 Web 表示基盤の通信 | 未解決。現状は既定ブラウザー（Edge のアプリ窓）で表示するため、**ブラウザー自体の通信は止められません**（下記） |

## 未検証・残っている課題

- **デスクトップアプリ（Claude / Codex / Antigravity の GUI）からの接続と長時間待機は未実測**です（作成時に画面を操作できなかったため）。L2 が成り立つか、保留が何秒まで通るか、待機中に使用枠を消費するかは、実際に使うと自動で計測・表示されます。CLI での成功をアプリの証拠にはしていません。
- Antigravity：設定ファイルへの登録は実装済みだが、実機の読込・CLI アダプターは未検証。
- 表示基盤：専用のウィンドウ基盤（WebView2 / Tauri 等）ではなくブラウザーの窓です。IdleShift のプロセスは通信しませんが、ブラウザー本体の通信（更新確認等）は別です。完全な無通信の検証（プロセスツリー全体・DNS）は未実施。
- 配布物は未署名です。SHA-256 を添付していますが、SmartScreen の警告が出ます。コード署名証明書（有料）は人の判断が必要です。
- 既存の Markdown 形式の黒板からの取込は未実装（レビューでも後回し）。
- Windows 専用（Mac / Linux は未対応）。会話の自動圧縮を跨いだ継続（V6）と、実際の枠切れからの復帰（V7）は未遭遇。
- 非開発者による通し試験（V10）は未実施。
